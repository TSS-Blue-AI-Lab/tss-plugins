# Divergence

## The failure mode

Four options that are one option wearing different hats. The user reacts weakly because there was never a real choice, and the session produces nothing.

The test, applied before showing anything:

> Does each option answer a different *question*, or the same question with a different parameter?

Blue versus green is a parameter. A dashboard that leads with a single number versus one that leads with a chart versus one that leads with a list of anomalies — those are different answers to *what is this page for*. Diverge on the decision, not the setting.

Second test:

> If the user picked this one, would the work be meaningfully different?

If two options collapse to the same implementation, they are one option.

## Composition

- **Four by default.** Fewer than three isn't a spread; more than six can't be held in the head at once. Scale up only when the user asks for a long list.
- **One deliberate outlier.** Include something the user probably won't pick — more radical, cheaper than seems reasonable, or from a different discipline entirely. Rejecting it is informative in a way that rejecting a near-miss is not, and occasionally it wins.
- **Order along a stated axis.** Cheapest to most ambitious, safest to most radical, smallest to largest blast radius. Name the axis out loud. An unordered list makes the user do the ranking work.
- **No option is a strawman in the pejorative sense.** Every one is the best version of its own idea. A deliberately weak option teaches nothing.

## Option card

```
### N. <Name — memorable, so the user can refer to it>

<One line: what this actually is.>

Costs:      <effort, and what it makes harder later>
Assumes:    <what has to be true for this to work>
Rules out:  <what picking this closes off>
```

Keep each card short enough that four fit on a screen. The user is comparing, not reading.

For a "places we could intervene" style list, the same card applies — `Costs` carries the cheapest-to-most-ambitious ordering that makes the list useful.

## Closing the pass

Ask two things, together:

1. Which of these resonate?
2. What is wrong with the others?

The second question does the work. A user who says "3 is closest but the sidebar is doing too much" has just specified something they could not have stated cold. Follow that thread — see Phase 3 in `SKILL.md`.

Never ask the user to rank all options. They will comply and it will be noise.
